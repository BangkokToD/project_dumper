# Project Dumper

**Project Dumper** — настольное приложение на **PyQt6** для быстрого получения «снимка» проекта:
дерево каталогов, содержимое файлов и интерактивный просмотр diff с подсветкой и копированием.

Приложение ориентировано на разработчиков и удобно для:

* ревью кода,
* подготовки отчётов и документации,
* анализа сторонних репозиториев,
* сравнения изменений,
* передачи контекста в другие инструменты (включая ИИ).

---

## Возможности

### Обзор проекта

* Просмотр структуры проекта в виде дерева.
* Чтение текстовых файлов с автоопределением кодировки.
* Игнорирование бинарных файлов и «мусорных» директорий.
* Поддержка `.gitignore` (динамическая, с кешированием).
* Ограничения по размеру файлов.

### Режимы сканирования

В приложении доступны три режима:

* **Дерево + файлы** — режим по умолчанию.
  Отображается дерево проекта и содержимое файлов.

* **Только файлы** — дерево не включается в результат, выводятся только файлы.

* **Только дерево** — выводится только структура проекта без содержимого файлов.

Режим выбирается перед запуском сканирования и влияет на формирование итогового дампа.


В дереве проекта папки можно **сворачивать вручную**.

Семантика следующая:

* **Свёрнутая папка (collapsed)**:

  * в дереве отображается сама папка;
  * её содержимое заменяется на символ `…`;
  * **содержимое этой папки НЕ попадает в дамп файлов** по умолчанию.

* **Кнопка «Игнор сворачивание»**:

  * выполняет **разовый скан**, игнорируя состояние свёрнутых папок;
  * временно считает все папки развёрнутыми **только для текущего сканирования**;
  * состояние дерева (что было свёрнуто/развёрнуто) **не изменяется**.

Таким образом:

* обычный скан уважает состояние дерева;
* скан с игнорированием — показывает и дампит всё, независимо от сворачивания.

### Ручное скрытие файлов (исключение)

Файлы в дереве можно **вручную исключать** (двойной клик):

* исключённый файл:

  * остаётся видимым в дереве;
  * отображается зачёркнутым;
  * **не попадает в дамп файлов** по умолчанию.

Поведение при игнорировании:

* при сканировании с кнопкой **«Игнор сворачивание»**:

  * вручную исключённые файлы **включаются обратно** в дамп.

Это позволяет:

* временно скрывать файлы при обычной работе;
* получать полный дамп при необходимости, без изменения состояния дерева.

### Diff-просмотр

* Подсветка:

  * `+` — добавления,
  * `-` — удаления,
  * `diff --git` и служебные заголовки — серым,
  * заголовки `@@ ... @@` — подсвечивается только сам сегмент `@@ ... @@`.
* Копирование по клику:

  * обычный клик — одна строка;
  * клик с модификатором (Ctrl / Shift / Alt / Ctrl+Shift — настраивается) —
    копирование группы строк.
* Анимация подсветки при копировании (настраиваемая).

### Экспорт

* Форматы: **txt**, **md**, **json**.
* Экспорт с деревом или без него (в зависимости от режима).

### Внешний вид

* Независимые **светлая** и **тёмная** темы.
* Переключение темы без перезапуска.
* Иконка и тема сохраняются в настройках.

### Настройки приложения

Раздел **«Настройки»** организован по категориям.

* Настройки сгруппированы логически (Файлы, Diff, Внешний вид).
* Каждая категория оформлена как **разворачиваемый блок**.
* Это позволяет:

  * не перегружать интерфейс;
  * быстро находить нужные параметры.

Изменения можно:

* применить сразу;
* сохранить как значения по умолчанию.

## Установка (рекомендуется)

### AppImage (Linux)

Это основной и рекомендуемый способ.

1. Скачай файл из **Releases**:

   * `ProjectDumper-light.AppImage`
   * или `ProjectDumper-dark.AppImage`

2. Сделай файл исполняемым:

   ```bash
   chmod +x ProjectDumper-light.AppImage
   ```

3. Запусти:

   ```bash
   ./ProjectDumper-light.AppImage
   ```

---

## Быстрый старт

1. Запусти приложение.
2. Укажи путь к проекту.
3. Выбери режим сканирования:

   * Дерево + файлы / Только файлы / Только дерево.
4. Нажми **Сканировать**.
5. При необходимости:

   * скопируй результат,
   * сохрани в файл,
   * переключись на вкладку **Diff**.

## Установка в систему (опционально)

Для отображения иконки в меню приложений рекомендуется интеграция AppImage.

### Способ 1: AppImageLauncher (рекомендуется)

* Установи **AppImageLauncher** из репозиториев.
* Запусти AppImage и согласись на интеграцию.
* После этого приложение появится в меню с иконкой.

### Способ 2: вручную

1. Скопируй AppImage, например, в `~/Applications`.
2. Создай `.desktop`-файл в `~/.local/share/applications/`.
3. Укажи путь к AppImage и `Icon=project-dumper`.

## Настройки и хранение данных

### Где хранятся настройки

Все настройки сохраняются **рядом с AppImage**:

```
.project_dumper.json
```

Особенности:

* HOME-конфиг (`~/.project_dumper.json`) **не используется**;
* каждая копия AppImage может иметь собственные настройки;
* приложение полностью переносимо вместе с конфигом.

### Поведение при первом запуске

* если portable-конфиг отсутствует:

  * используется конфигурация по умолчанию;
  * тема определяется сборкой (`light` / `dark`);
* после нажатия **«Сохранить по умолчанию»**:

  * portable-конфиг создаётся рядом с AppImage.

### Иконки

Если рядом с AppImage нет иконок, они создаются автоматически:

```
resources/icons/
  app_light.png
  app_dark.png
```

## Запуск из исходников (для разработки)

### Требования

* Python **3.12**
* Linux

### Установка

```bash
git clone https://github.com/BangkokToD/project_dumper.git
cd project_dumper
python3.12 -m venv .venv
source .venv/bin/activate
pip install -U pip
pip install -e ".[dev]"
```

### Запуск

```bash
python -m project_dumper
```

### Тесты

* **Unit и integration тесты** запускаются по умолчанию:

  ```bash
  pytest -q
  ```
* **GUI-тесты**:

  * не запускаются в CI;
  * выполняются вручную при необходимости:

    ```bash
    pytest -q -m gui
    ```

## Архитектура проекта (кратко)

```
config/          — модель и хранение конфигурации (portable)
domain/          — чистая бизнес-логика
infrastructure/  — адаптеры к ФС и окружению
services/        — use-case сервисы
presentation/ui/ — PyQt6 UI
project_dumper/  — пакет и точка входа
scripts/         — сборка AppImage
tests/           — unit / integration / gui
```

Архитектура построена так, чтобы:

* UI не содержал бизнес-логики;
* домен и сервисы были тестируемыми;
* сборка AppImage была воспроизводимой.

## Сборка AppImage локально

```bash
./scripts/build_appimage.sh
```

```
dist_appimage/
  ProjectDumper-light.AppImage
  ProjectDumper-dark.AppImage
```

## CI / релизы

* На каждый push:

  * прогоняются тесты (без GUI),
  * собираются AppImage (light + dark),
  * артефакты доступны в GitHub Actions.
* На тег `vX.Y.Z`:

  * автоматически создаётся GitHub Release,
  * прикладываются оба AppImage и `SHA256SUMS.txt`.
