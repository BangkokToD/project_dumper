# Project Dumper

**Project Dumper** — настольное приложение на **PyQt6** для быстрого получения «снимка» проекта:
дерево каталогов, содержимое файлов и интерактивный просмотр diff с подсветкой и копированием.

Приложение ориентировано на разработчиков и удобно для:

* ревью кода,
* подготовки отчётов и документации,
* анализа сторонних репозиториев,
* сравнения изменений,
* передачи контекста в другие инструменты (включая ИИ).

---

## Возможности

### Обзор проекта

* Просмотр структуры проекта в виде дерева.
* Чтение текстовых файлов с автоопределением кодировки.
* Игнорирование бинарных файлов и «мусорных» директорий.
* Поддержка `.gitignore` (динамическая, с кешированием).
* Ограничения по размеру файлов.

### Режимы сканирования

В приложении доступны три режима:

* **Дерево + файлы** — режим по умолчанию.
  Отображается дерево проекта и содержимое файлов.

* **Только файлы** — дерево не включается в результат, выводятся только файлы.

* **Только дерево** — выводится только структура проекта без содержимого файлов.

Режим выбирается перед запуском сканирования и влияет на формирование итогового дампа.


В дереве проекта папки можно **сворачивать вручную**.

Семантика следующая:

* **Свёрнутая папка (collapsed)**:

  * в дереве отображается сама папка;
  * её содержимое заменяется на символ `…`;
  * **содержимое этой папки НЕ попадает в дамп файлов** по умолчанию.

* **Кнопка «Игнор сворачивание»**:

  * выполняет **разовый скан**, игнорируя состояние свёрнутых папок;
  * временно считает все папки развёрнутыми **только для текущего сканирования**;
  * состояние дерева (что было свёрнуто/развёрнуто) **не изменяется**.

Таким образом:

* обычный скан уважает состояние дерева;
* скан с игнорированием — показывает и дампит всё, независимо от сворачивания.

### Ручное скрытие файлов (исключение)

Файлы в дереве можно **вручную исключать** (двойной клик):

* исключённый файл:

  * остаётся видимым в дереве;
  * отображается зачёркнутым;
  * **не попадает в дамп файлов** по умолчанию.

Поведение при игнорировании:

* при сканировании с кнопкой **«Игнор сворачивание»**:

  * вручную исключённые файлы **включаются обратно** в дамп.

Это позволяет:

* временно скрывать файлы при обычной работе;
* получать полный дамп при необходимости, без изменения состояния дерева.


### Вкладка «Список»

Вкладка **«Список»** нужна, когда не нужен полный дамп дерева, а нужно быстро получить дамп
**только по конкретным путям/паттернам** (например, из задачи/списка файлов/дифа).

**UI:**
* слева — многострочный ввод: **одна строка = один путь или паттерн**;
* справа — результат (дамп совпавших файлов);
* сверху выбирается формат (**md / txt / json**), доступны кнопки **Сканировать / Копировать / Сохранить / Очистить**.

#### Настройки → Список

* **«* рекурсивная»** — делает `*.py` рекурсивным (аналог `**/*.py`).
* **«Игнорировать фильтры»** — сканирует совпадения, не учитывая фильтры (например `.gitignore` и прочие правила исключения).
* **«Если паттерн совпал с директорией — включать файлы из неё»** — если паттерн совпал с директорией, включает файлы из этой директории
  (иначе это считается `0 matches`).

#### Примеры (минимум)

1) Явный путь к файлу:

```text
README.md
````

2. Паттерн `domain/*`:

```text
domain/*
```

3. Паттерн `*.py` + включённая **«* рекурсивная»**:

```text
*.py
```

#### Проблемные строки

Если во вкладке **«Список»** найдены проблемные строки, приложение показывает отдельную модалку.

К проблемам относятся:

* несуществующий файл;
* некорректный glob-паттерн;
* паттерн без совпадений;
* файл, скрытый настройками;
* файл, пропущенный из-за размера или бинарного содержимого;
* ошибка чтения файла.

В модалке у каждой строки есть чекбокс:

* выключен — строка будет удалена из левого поля ввода;
* включён — строка останется.

После закрытия модалки автоматический перескан **не запускается**. Чтобы проверить оставшийся список, нужно нажать **«Сканировать»** вручную. Клик по значению строки копирует путь или паттерн в буфер обмена.

### Diff-просмотр

* Подсветка:

  * `+` — добавления,
  * `-` — удаления,
  * `diff --git` и служебные заголовки — серым,
  * заголовки `@@ ... @@` — подсвечивается только сам сегмент `@@ ... @@`.
* Копирование по клику:

  * обычный клик — одна строка;
  * клик с модификатором (Ctrl / Shift / Alt / Ctrl+Shift — настраивается) —
    копирование группы строк.
* Анимация подсветки при копировании (настраиваемая).

### Вкладка «Текст»

Вкладка **«Текст»** предназначена для быстрой очистки произвольного текста от пустых строк.

**UI:**

* слева — исходный текст;
* справа — результат;
* кнопка **Сканировать** удаляет пустые строки;
* результат можно скопировать, сохранить в `.txt` или очистить.

#### Настройки → Текст

* **«Сохранять отступы --- и * * *»** — если настройка включена, приложение удаляет пустые строки,

По умолчанию настройка включена.

### Вкладка «Замена»

Вкладка **«Замена»** предназначена для безопасной массовой замены русских терминов и их словоформ в проекте.

Она полезна, когда нужно заменить термин в большом количестве файлов, но перед записью важно увидеть каждое конкретное изменение и вручную отключить лишние замены.

#### Основной сценарий

1. Открой вкладку **«Замена»**.

2. В поле **«Проект»** укажи путь к директории проекта.

3. В поле **«Термин»** укажи базовый русский термин, например:

   ```text
   супервайзер
   ```

4. Нажми **«Сканировать»**.

После сканирования приложение:

* обходит текстовые файлы проекта;
* учитывает текущие правила Project Dumper: `.gitignore`, скрытые файлы, `ignore_dirs`, `ignore_files`, лимит размера файла, бинарность, кодировку и другие настройки чтения;
* ищет русские слова, которые начинаются с указанного термина;
* группирует найденные формы по точному написанию и регистру.

Например, для термина `супервайзер` могут быть найдены формы:

```text
Супервайзер
супервайзер
Супервайзера
Супервайзеру
```

#### Таблица форм

После сканирования найденные формы отображаются в таблице:

```text
Вкл. | Форма | Кол-во | Файлов | Замена | К применению
```

Назначение колонок:

* **Вкл.** — включает или выключает форму целиком.
* **Форма** — точное найденное написание.
* **Кол-во** — сколько раз форма найдена.
* **Файлов** — в скольких файлах форма встретилась.
* **Замена** — ручной текст замены для этой формы.
* **К применению** — сколько конкретных изменений сейчас включено в preview.

Все найденные формы включены по умолчанию.

В колонке **«Замена»** нужно вручную указать replacement для каждой нужной формы:

```text
Супервайзер   → Руководитель
супервайзер   → руководитель
Супервайзера  → Руководителя
```

Если replacement пустой, эта форма не участвует в preview и применении.

#### Preview

После заполнения замен нажми **«Preview»**.

Приложение строит preview внутри вкладки и группирует изменения по файлам:

```text
File: README.md

[✓] Line 42
Было:
... Супервайзер проверил задачу ...

Стало:
... Руководитель проверил задачу ...
```

В preview:

* показывается только строка с заменой;
* номер строки отображается обязательно;
* в блоке **«Было»** подсвечивается исходная форма;
* в блоке **«Стало»** подсвечивается replacement;
* replacement в preview не редактируется;
* каждое конкретное вхождение имеет отдельную карточку;
* если в одной строке несколько замен, они отображаются отдельными карточками.

У каждой preview-карточки есть отдельный checkbox.

Если снять checkbox у конкретной карточки:

* отключается только это конкретное изменение;
* форма в таблице остаётся включённой;
* счётчик **«К применению»** обновляется.

Например:

```text
54 / 54
53 / 54
0 / 3
```

#### Когда preview сбрасывается

Preview считается устаревшим и сбрасывается, если изменить:

* поле **«Проект»**;
* поле **«Термин»**;
* checkbox формы в таблице;
* replacement в таблице;
* загруженную карту замен;
* результаты повторного сканирования;
* состояние вкладки через **«Очистить»**.

После сброса:

* preview-зона очищается;
* кнопка **«Применить отмеченные»** становится неактивной;
* счётчики **«К применению»** возвращаются к `—`.

#### Применение замен

После проверки preview нажми **«Применить отмеченные»**.

Перед применением:

* если в корне проекта есть `.git`, приложение показывает предупреждение:

  ```text
  Перед массовой заменой убедитесь, что важные изменения закоммичены.
  Project Dumper не создаёт backup.
  ```

* пользователь должен подтвердить применение;

* приложение перечитывает файлы из preview;

* для каждого файла проверяется hash содержимого.

Если файл не изменился после построения preview, отмеченные изменения применяются.

Если файл изменился после построения preview:

* этот файл не перезаписывается;
* все изменения этого файла считаются пропущенными;
* файл попадает в список конфликтов;
* остальные файлы без конфликта продолжают применяться.

После применения показывается отчёт:

```text
Изменено файлов: N
Применено замен: N
Пропущено замен: N
Конфликты: N
```

Если есть конфликты, отчёт дополнительно показывает список файлов:

```text
Файлы изменились после preview:
- path/to/file.py
- path/to/other.py

Постройте preview заново.
```

При конфликте нужно заново нажать **«Preview»** и повторно проверить изменения.

#### Backup

Project Dumper **не создаёт backup** перед массовой заменой.

Ожидаемый workflow — работа в git:

1. Перед применением убедись, что важные изменения закоммичены.
2. Построй preview.
3. Примени отмеченные изменения.
4. Проверь результат через `git diff`.
5. При необходимости откати изменения средствами git.

#### JSON-карты замен

Вкладка **«Замена»** поддерживает сохранение и загрузку JSON-карт замен.

Карта замен хранит только правила по найденным формам:

```json
{
  "version": 1,
  "source_term": "супервайзер",
  "rules": [
    {
      "source": "Супервайзер",
      "replacement": "Руководитель",
      "enabled": true
    }
  ]
}
```

Карта не хранит:

* конкретные файлы;
* строки;
* позиции;
* preview;
* hash файлов.

Это сделано потому, что файлы проекта могут измениться, и конкретные позиции быстро устаревают.

Кнопка **«Сохранить карту»**:

* берёт текущий термин;
* собирает формы, replacement и состояние checkbox из таблицы;
* сохраняет JSON-файл.

Кнопка **«Загрузить карту»**:

* читает JSON-файл;
* заполняет поле **«Термин»**;
* применяет rules к уже найденным формам, если таблица заполнена;
* если таблица ещё пустая, сохраняет карту в состоянии вкладки и применяет её после следующего сканирования.

Если JSON битый или структура карты неверная, приложение показывает понятную ошибку.

### Экспорт

* Формат по умолчанию: **md**.
* Доступные форматы: **md**, **txt**, **json**.
* Экспорт с деревом или без него (в зависимости от режима).
* JSON-формат сохранён без изменений.

Если конфиг отсутствует или в нём сохранено битое значение `output_format`, используется `md`.
Старые пользовательские конфиги с валидными значениями `txt`, `md` или `json` не мигрируются принудительно.

#### Markdown-формат

Markdown-дамп не содержит общего верхнего заголовка проекта.

Если дерево включено, результат начинается так:

````markdown
## Структура проекта

```text
project_dumper/
├── config
│   └── model.py
└── README.md
```

## FILE: config/model.py

```python
...
```
````

Во вкладке **«Список»** дерево не выводится, поэтому Markdown начинается сразу с файлов:

````markdown
## FILE: config/model.py

```python
...
```
````

Каждый файл выводится как:

````markdown
## FILE: relative/path/to/file.py

```python
...
```
````

Язык fenced code block определяется по расширению файла:

| Расширение       | Язык         |
| ---------------- | ------------ |
| `.py`            | `python`     |
| `.md`            | `markdown`   |
| `.json`          | `json`       |
| `.toml`          | `toml`       |
| `.yml` / `.yaml` | `yaml`       |
| `.sh`            | `bash`       |
| `.html`          | `html`       |
| `.css`           | `css`        |
| `.js`            | `javascript` |
| `.ts`            | `typescript` |
| `.txt`           | `text`       |

Для неизвестных расширений используется `text`.

TXT-дамп пишет заголовки файлов как `FILE: path`. JSON оставляет поле `path` без префикса `FILE:`.

### Внешний вид

* Независимые **светлая** и **тёмная** темы.
* Переключение темы без перезапуска.
* Иконка и тема сохраняются в настройках.

### Настройки приложения

Раздел **«Настройки»** организован по категориям.

* Настройки сгруппированы логически (Файлы, Список, Diff, Текст, Внешний вид).
* Каждая категория оформлена как **разворачиваемый блок**.
* Это позволяет:

  * не перегружать интерфейс;
  * быстро находить нужные параметры.

Изменения можно:

* применить сразу;
* сохранить как значения по умолчанию.

## Установка (рекомендуется)

### AppImage (Linux)

Это основной и рекомендуемый способ.

1. Скачай файл из **Releases**:

   * `ProjectDumper-light.AppImage`
   * или `ProjectDumper-dark.AppImage`

2. Сделай файл исполняемым:

   ```bash
   chmod +x ProjectDumper-light.AppImage
   ```

3. Запусти:

   ```bash
   ./ProjectDumper-light.AppImage
   ```

## Быстрый старт

1. Запусти приложение.
2. Укажи путь к проекту.
3. Выбери режим сканирования:

   * Дерево + файлы / Только файлы / Только дерево.
4. Нажми **Сканировать**.
5. При необходимости:

   * скопируй результат,
   * сохрани в файл,
   * переключись на вкладку **Diff**.

## Установка в систему (опционально)

Для отображения иконки в меню приложений рекомендуется интеграция AppImage.

### Способ 1: AppImageLauncher (рекомендуется)

* Установи **AppImageLauncher** из репозиториев.
* Запусти AppImage и согласись на интеграцию.
* После этого приложение появится в меню с иконкой.

### Способ 2: вручную

1. Скопируй AppImage, например, в `~/Applications`.
2. Создай `.desktop`-файл в `~/.local/share/applications/`.
3. Укажи путь к AppImage и `Icon=project-dumper`.

## Настройки и хранение данных

### Где хранятся настройки

Все настройки сохраняются **рядом с AppImage**:

```
.project_dumper.json
```

Особенности:

* HOME-конфиг (`~/.project_dumper.json`) **не используется**;
* каждая копия AppImage может иметь собственные настройки;
* приложение полностью переносимо вместе с конфигом.

### Поведение при первом запуске

* если portable-конфиг отсутствует:

  * используется конфигурация по умолчанию;
  * тема определяется сборкой (`light` / `dark`);
* после нажатия **«Сохранить по умолчанию»**:

  * portable-конфиг создаётся рядом с AppImage.

### Иконки

Если рядом с AppImage нет иконок, они создаются автоматически:

```
resources/icons/
  app_light.png
  app_dark.png
```

git clone https://github.com/BangkokToD/project_dumper.git
cd project_dumper
python3.12 -m venv .venv

python -m project_dumper

## Архитектура проекта (кратко)

```
config/          — модель и хранение конфигурации (portable)
domain/          — чистая бизнес-логика
infrastructure/  — адаптеры к ФС и окружению
services/        — use-case сервисы
presentation/ui/ — PyQt6 UI
project_dumper/  — пакет и точка входа
scripts/         — сборка AppImage
tests/           — unit / integration / gui
```

Архитектура построена так, чтобы:

* UI не содержал бизнес-логики;
* домен и сервисы были тестируемыми;
* сборка AppImage была воспроизводимой.
