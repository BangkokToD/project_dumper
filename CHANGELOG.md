# Changelog

## 0.6.1 — 2026-05-29

### Changed

- Во вкладке «Список» после закрытия модалки проблемных строк автоматически запускается повторное сканирование, если в списке остались строки.

### Fixed

- Если после удаления проблемных строк список стал пустым, результат очищается без лишнего повторного warning о пустом списке.

## 0.6.0 — 2026-05-29

### Added

- Вкладка «Замена» для безопасной массовой замены русских словоформ в проекте.
- Группировка найденных форм по точному написанию и регистру.
- Интерактивный preview изменений в формате «Было / Стало».
- Возможность отключить каждое конкретное изменение перед применением.
- Сохранение и загрузка JSON-карты замен.
- Проверка изменения файла после preview перед записью.

### Changed

- Главное окно подключает вкладку «Замена» через отдельный UI-модуль без переноса бизнес-логики в `main_window.py`.

## 0.5.0 — 2026-05-27

### Added

- Кастомная модалка проблемных строк во вкладке «Список».
- Клик по значению проблемной строки в модалке копирует его в буфер обмена.

### Changed

- Markdown стал форматом по умолчанию для новых и битых конфигов.
- Markdown-дамп теперь использует `## Структура проекта`, `## FILE: ...` и fenced code blocks с определением языка по расширению.
- TXT-дамп теперь пишет заголовки файлов как `FILE: ...`.
- Вкладка «Список» теперь предлагает удалить проблемные строки без автоматического перескана после закрытия модалки.

### Unchanged

- JSON-формат сохранён без изменений.
- Старые пользовательские конфиги с валидным `output_format` не мигрируются принудительно.


## 0.4.0 — 2026-05-13

### Added

- Вкладка «Текст» для очистки произвольного текста от пустых строк.
- Настройка «Сохранять отступы --- и * * *» в разделе «Настройки → Текст».

### Changed

- README обновлён с описанием вкладки «Текст» и новой настройки.


## 0.3.0 — 2026-02-09

### Added

- Вкладка «Список».
- Настройки «Список» в разделе «Настройки» (list_scan.*).



## 0.2.0 — 2026-01-29

### Fixed

- **Экспорт:** выбор формата в UI (txt/json/md) имеет приоритет для текущего запуска (оверрайд поверх конфига).
- **Спец-файлы:** `.env` по умолчанию скрыт и появляется только при `include_env=true`; при включении `.env` не исключается правилами `.gitignore`.
  `.env.example` и `.gitignore` видимы при `ignore_hidden=true` и попадают в дамп.
- **Nested `.gitignore`:** паттерны с ведущим `/` во вложенных `.gitignore` якорятся к директории этого `.gitignore` (исправлен `base_rel`).
